A quarter in India's cybersecurity resilience changes only when you can point to a dated public instrument, or to a control you operate, that started or stopped inside that quarter. This page states that test. It does not name a change for any quarter.

## The two rows that qualify

Use a row only if you can open it.

- **A duty.** A notification, a licence amendment, a rule, or a direction whose date falls in the quarter, and that changes what an entity must do. The Department of Telecommunications shelf for the telecom slice is [dot.gov.in](https://www.dot.gov.in/). The instrument is the notification, not the ministry homepage.
- **A control.** Something you already run — a security test before connection, a trusted-source check on equipment, an incident report, an audit finding — that produced a record in the quarter and did not produce it in the quarter before, or the reverse.

A speech, a homepage refresh, a training event, and a research-index URL fail both rows. Nomura's research pages were paired with an earlier draft of this file. They are not a quarterly cyber record, so that link is omitted.

## How to file the quarter

Write the quarter as calendar dates. For each candidate, record the title, the date printed on the document, the duty that differs, and the entity that must act. If the date is missing, the item is not in the quarter. If you cannot name the earlier text the new one changes, send it to the [policy-shift test](/blog/cybersecurity-resilience-policy-shift-explainer-dot-gov-20260330-151) instead of calling it a change.

Telecom duties and incident duties are different shelves. A Department of Telecommunications amendment does not, by itself, change a CERT-In reporting clock. A CERT-In direction does not, by itself, clear a product for connection to a telecom network. File them on separate lines.
